# Техническое задание на разработку веб-редактора PDF-переводов

## 1. Введение

### 1.1. Назначение
Разработать веб-приложение, позволяющее пользователю:
- Загружать PDF-документ (исходный или уже переведённый нашим CLI-инструментом).
- Визуально просматривать страницы документа с наложенными текстовыми блоками (параграфы, заголовки, таблицы).
- Редактировать текст перевода, изменять геометрию (позицию и размер) блоков, управлять шрифтами.
- Сохранять изменения в JSON и/или генерировать итоговый PDF.

### 1.2. Цели
- Обеспечить удобную ручную коррекцию перевода (исправление ошибок LLM, адаптация под стиль, правка таблиц).
- Сократить время постобработки по сравнению с редактированием JSON вручную.
- Интегрироваться с существующим бэкендом (Python FastAPI, Redis, PyMuPDF).

### 1.3. Целевая аудитория
- Технические редакторы, переводчики, инженеры, работающие с техническими PDF на русском/английском.

## 2. Требования к функциональности

### 2.1. Основные возможности

#### 2.1.1. Загрузка и парсинг
- Загрузить PDF через веб-форму (drag & drop или выбор файла).
- Отправить PDF на бэкенд, где он обрабатывается существующим `PDFParserService` → возвращается структура `blocks` (с текстом, координатами, типом).
- Полученные блоки отображаются на канвасе поверх каждой страницы PDF.

#### 2.1.2. Визуализация страниц
- Каждая страница отображается с использованием **PDF.js** (рендеринг в `canvas`).
- Поверх страницы рисуются **прямоугольники блоков** (с разными цветами: синий – параграф, зелёный – заголовок, оранжевый – таблица).
- Блок можно выделить, подсветить, перемещать.

#### 2.1.3. Редактирование текста
- Двойной клик по блоку → появляется текстовый редактор (`<textarea>` или `contenteditable`).
- Изменение текста сохраняется в структуре блоков (в памяти, затем в Redis).
- Поддержка сохранения форматирования **только простого текста** (шрифт, размер, выравнивание – в будущем).

#### 2.1.4. Редактирование позиции и размера
- Возможность перетаскивать блок в любую точку страницы.
- Изменять размер блока (растягивать за углы).
- При перемещении/изменении размера обновляются координаты `bbox` в метаданных.
- Для таблиц – перемещение всей таблицы целиком (изменение позиции, а не ячеек).

#### 2.1.5. Управление таблицами
- Отображение таблиц как набора ячеек (сетка).
- Редактирование текста в ячейках.
- Изменение ширины/высоты столбцов и строк (интерактивно).
- Добавление/удаление строк или столбцов (опционально).

#### 2.1.6. Панель инструментов
- Кнопка **«Сохранить в JSON»** – выгружает текущее состояние блоков в файл (JSON с теми же полями, что и `--export-json`).
- Кнопка **«Сгенерировать PDF»** – вызывает `PDFGeneratorService` (PyMuPDF) на бэкенде и возвращает готовый PDF для скачивания.
- Кнопка **«Загрузить другой PDF»** – сброс текущего состояния.
- Кнопка **«Отменить/повторить»** (Undo/Redo) для текста и перемещений.

#### 2.1.7. Навигация
- Пагинация: кнопки «Предыдущая страница», «Следующая страница».
- Выбор страницы из выпадающего списка.
- Масштабирование (зум) страницы.

### 2.2. Дополнительные возможности (опционально, для следующей версии)
- Поддержка работы с глоссарием (подсветка терминов, быстрая замена).
- Одновременное редактирование нескольких документов.
- Автосохранение черновиков в Redis.
- Тёмная/светлая тема.

## 3. Технические требования

### 3.1. Бэкенд (Python + FastAPI)
- Эндпоинты:
  - `POST /upload` – принимает PDF, возвращает `session_id` и структуру `blocks`.
  - `GET /blocks/{session_id}` – получить текущие блоки (с учётом редактирования).
  - `POST /blocks/{session_id}` – сохранить обновлённые блоки (при каждом редактировании).
  - `POST /generate/{session_id}` – сгенерировать PDF из текущих блоков (вызвать `PDFGeneratorService`).
  - `GET /download/{session_id}` – скачать итоговый PDF.
- Хранение состояния сессии (блоков) – Redis (TTL 24 часа).
- Использовать существующие сервисы: `PDFParserService`, `PDFGeneratorService`.

### 3.2. Фронтенд (HTML, CSS, JS)
- **PDF.js** – отображение страниц PDF и получение размеров.
- **Fabric.js** – работа с интерактивными объектами (прямоугольники, перемещение, резизайз).
- **Axios** / Fetch API – общение с бэкендом.
- **Tailwind CSS** (или любой другой) – минимальный современный интерфейс.

### 3.3. Интеграция с существующим кодом
- Не переписывать существующие сервисы, а вызывать их из новых API-контроллеров.
- Формат JSON блоков – тот же, что используется в `translate.py --export-json`, чтобы можно было загружать отредактированные вручную JSON.

### 3.4. Производительность
- Загрузка PDF и получение блоков – не более 5 секунд для 50 страниц.
- Редактирование должно быть плавным, без лагов при перетаскивании.

### 3.5. Безопасность
- Валидация загружаемых файлов (PDF, размер до 50 МБ).
- Очистка сессий Redis по истечении TTL.
- Защита от CSRF (использовать SameSite cookies или токены).

## 5. Критерии приёмки

- Пользователь может загрузить PDF и увидеть страницы с наложенными блоками.
- Редактирование текста сохраняется и отображается в JSON и итоговом PDF.
- Перемещение/изменение размера блока корректно обновляет координаты.
- Сгенерированный PDF сохраняет все изменения, изображения и фоны исходного документа.
- При повторной загрузке страницы состояние восстанавливается (благодаря сессии Redis).
- Время отклика интерфейса не превышает 1 секунду для типовых действий.
