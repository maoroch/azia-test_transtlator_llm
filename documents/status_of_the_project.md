# 🚀 PDF Technical Translator — Статус проекта

## 🎯 Цель

**Автоматический перевод технических PDF‑документов** (руководства, спецификации, патенты, декларации) с сохранением структуры, таблиц, графики, шрифтов и оформления.

---

## ✅ Что уже сделано (промышленная версия, апрель 2026)

### 1. Извлечение и сегментация (`pdfplumber`)
- 📄 Извлечение текста с точными координатами (`words_to_blocks_v2` — правильная расстановка пробелов).
- 📏 Сохранение типа блока (заголовок, параграф, список, таблица) на основе шрифтов и позиционирования.
- 🧹 **Очистка текста:** удаление мягких переносов, лишних дефисов, нормализация пробелов.
- 🔗 **Объединение коротких блоков** (последовательные фрагменты <60 символов сливаются в один).
- 🗂️ Модели данных **Pydantic**: `Block`, `Table` (с координатами ячеек), `Document`.

### 2. ML‑слой (перевод)
- 🤖 **Два бэкенда:** Groq API (`llama-3.3-70b-versatile`) и Ollama (`llama3:8b`).
- 📝 Системный промпт + пользовательский глоссарий.
- 📄 **Постраничный перевод** — один запрос на страницу (с разбивкой, если блоков >20).
- 🗄️ **Redis‑кэш** (хеш текста + языки + глоссарий, TTL 24ч).
- ⏱️ **Rate limiting + retries** для Groq (30 запросов/мин, экспоненциальные задержки).
- ⚡ **Асинхронность и семафоры** — параллельные запросы с контролем лимитов.
- 📊 Логирование кэш‑хитов и вызовов API.

### 3. Таблицы
- 📑 Извлечение таблиц с координатами **каждой ячейки** (`page.find_tables()`).
- 🌐 **Перевод всей таблицы одним запросом** (JSON‑матрица) — обеспечивает согласованность терминов.
- 📐 **Автоматический подбор шрифта** (от 12 до 6 pt) и **динамическая высота строк** — текст не вылезает.
- 🖨️ Аккуратная отрисовка в PDF (центрирование, перенос слов).

### 4. Генерация PDF (PyMuPDF)
- 🖼️ **Сохранение всей графики, изображений, фонов** (оригинальный PDF не пересоздаётся).
- ✍️ Удаление оригинального текста (`add_redact_annot` + `apply_redactions`) и вставка перевода в те же координаты.
- 🔤 Автоматический перенос длинных строк (с учётом ширины блока).
- 🇷🇺 Поддержка кириллицы (системный шрифт Arial / DejaVuSans).

### 5. Производительность и масштабирование
- **Постраничный перевод** — один запрос на страницу (80 страниц → 80 запросов вместо 720).
- **Асинхронная обработка** (`asyncio.gather`) — параллельные запросы (5–10 одновременно).
- **Батчинг внутри страницы** — если страница содержит >20 блоков, она разбивается на несколько запросов.
- **Зануление кэша** для повторных запусков — мгновенный результат.

### 6. Экспорт / импорт JSON
- 💾 Флаг `--export-json` сохраняет все блоки, переводы, метаданные.
- ✏️ **Ручное редактирование** (текст, координаты, шрифты, ячейки таблиц).
- 🔁 **Генерация PDF из отредактированного JSON** (`generate_from_json.py`) без повторного перевода.

### 7. CLI и тестовый стенд
- ⚙️ Утилита `translate.py` с параметрами:
    ```bash
    --input, --output, --src-lang, --tgt-lang, --backend, --model, --batch-size, --export-json, --glossary, --no-cache
    ```
- 📈 Прогресс‑бары (tqdm) для таблиц и текстовых блоков.
- 🧪 Скрипт `create_big_doc.py` для генерации 80‑страничного технического PDF (нагрузочное тестирование).

### 8. Инфраструктура
- ⚙️ Конфигурация через `.env` (API ключи, лимиты, адрес Redis, параллельность).
- 📝 Логирование через loguru.
- 📦 Готов requirements.txt.
- 🧩 Сервис‑ориентированная архитектура (легко расширять).

## ⚠️ Текущие ограничения

- OCR не реализован — текст извлекается только из текстовых слоёв (сканы не поддерживаются).
- Сложные таблицы (объединённые ячейки, отсутствие сетки) могут распознаваться неточно — требуется доработка парсера.
- PyMuPDF при удалении текста может оставлять небольшие артефакты (редко).
- Ollama на CPU работает медленнее Groq (≈1–2 секунды на страницу), но безлимитно.
- Groq имеет суточный лимит токенов (100k на бесплатном тарифе). Для больших документов рекомендуются Ollama или платный тариф.

## 👥 Для команды / заказчика

Промышленный прототип полностью готов — справляется с документами объёмом 80+ страниц, сохраняет графику, переводит таблицы.

- **Выбор бэкенда:** Groq (быстро, платно, лимиты) vs Ollama (бесплатно, медленнее, безлимитно).
- **Ручная корректировка** возможна через `--export-json` и последующую генерацию.
- **Следующий шаг** — веб‑редактор для удобного визуального редактирования переведённых документов.
