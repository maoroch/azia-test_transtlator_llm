# PDF Technical Translator — Визуальный редактор перевода

> **LLM‑based перевод технических PDF с сохранением структуры, таблиц, графики и возможностью визуального редактирования**

Проект позволяет автоматически переводить технические PDF-документы (руководства, спецификации, патенты, декларации) с сохранением оригинального форматирования, таблиц и изображений. После перевода можно визуально редактировать текст, перемещать блоки, править ячейки таблиц и генерировать итоговый PDF.

---

## 🚀 Ключевые возможности

- **Извлечение текста и таблиц** с точными координатами (`pdfplumber`)
- **Определение логических блоков** (заголовки, параграфы, списки, таблицы) по шрифтам
- **Постраничный перевод** (один запрос на страницу) с батчингом и асинхронностью
- **Два бэкенда**: Groq API (облачный, быстрый) и Ollama (локальный, бесплатный)
- **Redis‑кэш** переводов (хеш текста + языки + глоссарий, TTL 24 ч)
- **Веб‑редактор** на чистом HTML/CSS/JS:
  - Загрузка PDF, просмотр страниц (PDF.js)
  - Наложение блоков (Fabric.js)
  - Редактирование текста (перевод / оригинал)
  - Перемещение и изменение размера блоков
  - Полноценная поддержка таблиц (ячейки, границы)
  - Экспорт в JSON и генерация итогового PDF
- **Генерация PDF** через PyMuPDF (сохранение графики, наложение переведённого текста)

## 📦 Установка и запуск

### Требования

- Python 3.12+
- Redis (локально или в Docker)
- Для бэкенда Groq: API ключ
- Для бэкенда Ollama: установленная и запущенная [Ollama](https://ollama.com/) (модель `llama3:8b`)

### 1. Клонирование и настройка окружения

```bash
git clone <repo>
cd pdf_translator
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2. Переменные окружения (`.env`)

```env
GROQ_API_KEY=your_groq_api_key          # нужно только для Groq
GROQ_RATE_LIMIT_PER_MINUTE=30
GROQ_MAX_CONCURRENT=5
REDIS_HOST=localhost
REDIS_PORT=6379
```

### 3. Запуск Redis

```bash
redis-server
```

### 4. Запуск бэкенда (FastAPI)

```bash
uvicorn src.web.api:app --reload --port 8000
```

### 5. Запуск фронтенда (из папки llm)

```bash
python -m http.server 8080
```

### 6. Открыть редактор

Откройте в браузере: [http://localhost:8080/index.html](http://localhost:8080/index.html)

## 🖥️ Использование

1. **Загрузить PDF** — кнопка «Загрузить PDF».
2. **Перевести документ** — кнопка «🌐 Перевести документ» (по умолчанию Groq; для Ollama измените в `src/web/api.py`).
3. **Редактировать текст**:
   - Двойной клик по текстовому блоку — редактирование.
   - Переключение режима «Перевод» / «Оригинал» (кнопка «✏️ Режим»).
   - Перемещение/изменение размера блоков — перетаскивание и угловые маркеры.
4. **Таблицы**:
   - Красные линии — границы.
   - Текст ячеек редактируется двойным кликом.
   - Перемещение ячеек пока недоступно (двигается вся таблица).
5. **Сохранить изменения**:
   - «💾 Сохранить JSON» — выгрузить текущее состояние блоков.
   - «📥 Сгенерировать PDF» — создать итоговый PDF с учётом всех правок.

```
│       └── models.py                  # Pydantic для API
├── index.html                         # редактор (фронтенд)

└── .env
```

## 🧪 Тестирование

Протестировано на:

- Простых текстовых PDF (`sample.pdf`)
- Таблицах с сеткой (`table_sample.pdf`)
- 80‑страничном техническом документе (`big_doc.pdf`)
- Декларации соответствия (сложный юридический текст)

Качество перевода зависит от выбранной LLM и глоссария. Для наилучших результатов с техническими терминами рекомендуется подготовить глоссарий (JSON).

## ⚠️ Известные ограничения

- OCR не реализован — сканированные PDF без текстового слоя не поддерживаются.
- Сложные макеты (многоколоночные, вложенные таблицы, графики) могут распознаваться неточно.
- Удаление текста в PyMuPDF иногда оставляет белый прямоугольник — можно вручную отредактировать позиции блоков в редакторе.
- Редактирование таблиц позволяет менять текст ячеек, но не добавлять/удалять строки/столбцы (будет в следующих версиях).
- Ollama на CPU работает медленнее Groq (≈ 2 секунды на страницу).
